# Phase 02 - Blocking Review Workflow

- **Phase objective:** integrate hook-enforced Rule Catalog review into the Engineer Slice lifecycle and require Developer disposition before completion, with citation enforcement that holds independent of Orchestrator's own compliance ([ADR 0001](../../../adr/0001-hook-enforced-rule-loading.md)).
- **User-visible outcome:** every completed Engineer Slice has either passed scoped Rule review or has documented Developer dispositions and any required revision re-reviewed.
- **Backend/data scope:** append-only JSON Lines Decision Journal; adoption-time Rule generation and activation; repository-level Copilot CLI hook configuration (`.github/hooks/*.json`) and hook scripts that invoke the Rule Catalog at `subagentStart`, `preToolUse`, and `subagentStop`; session-scoped tracking of which Rule IDs were loaded; Review Subagent defined as a user-defined custom agent; Orchestrator review-state handling.
- **UI/workflow scope:** combined numbered Finding report and per-Finding Developer dispositions.
- **Cross-slice invariants:** review scope is the Engineer Slice diff and directly affected Construction Paths; Review Subagent is a user-defined custom agent, never the built-in `general-purpose` agent, because `subagentStart`/`subagentStop` hook events do not fire for `general-purpose`; the Rule Catalog is invoked from hook scripts, not from Review Subagent's own tool calls — a `subagentStart` hook injects compact Rule Metadata into its prompt, and a `preToolUse` hook loads a full Rule body and records the loaded Rule ID for that review session; a `subagentStop` hook blocks completion, forcing another turn, whenever a reported Finding cites a Rule ID not recorded as loaded for that session, independent of Orchestrator's own handling of the response; all Findings appear together; unresolved Findings block completion; a dismissal remains specific to its Finding; Rules adopted through a decision are repository-wide by default; configuration failures fail closed.
- **Prerequisites:** Phase 01 Rule Catalog Foundation is completed; its public catalog behavior remains unchanged unless replanning is required; repository-level Copilot CLI hook support (`.github/hooks/*.json` with `subagentStart`, `preToolUse`, and `subagentStop` events) is available in every environment the Review Gate runs.
- **Acceptance checks:** a clean slice can complete after review; matching code produces an evidence-backed blocking Finding; compact Rule Metadata reaches Review Subagent via a `subagentStart` hook without any Catalog call from the subagent itself; Fix Once returns a focused Engineer revision; Adopt Rule and Fix creates and activates a complete Rule and records its path; Dismiss records a compact decision without suppressing future matches; a Finding citing a Rule ID not recorded as loaded through the hook path is blocked at `subagentStop`, independent of Orchestrator's own handling of the report; every required revision is re-reviewed.
- **Useful-if-stopped statement:** no partial wiring may allow Orchestrator, or Review Subagent's own self-report, to mark a slice complete after Engineer verification alone.
- **Risks and mitigations:** extending Orchestrator's existing completion rule can contradict its dispatch and status contract, so update the Review Subagent definition, Orchestrator definition, workflow documentation, agent catalog, artifact catalog, and related examples together; `preToolUse` command hooks fail closed on a crash or non-zero exit but fail open on a timeout, so a hung Catalog call could silently bypass enforcement — keep hook scripts minimal, synchronous, and covered by their own fast unit tests; no repository harness exists for firing real Copilot CLI hook events end-to-end, so hook scripts must be verified directly against their documented stdin/stdout contract using crafted fixtures, not through a live CLI session.
- **Test checkpoints:** preserve Phase 01 `node --test` catalog coverage; verify each hook script (`subagentStart`, `preToolUse`, `subagentStop`) directly by piping documented JSON input fixtures to it and asserting its stdout decision, using `node --test`; use focused documentation whitespace validation for contract artifacts. No repository Markdown link-check command exists, so link correctness requires explicit review until one is established. The phase's integration slice proves the hook scripts' composed behavior via fixture-driven invocation in sequence, not a live agent session.
- **Definition of done:** the documented Orchestrator loop, hook-enforced Rule Catalog invocation, Review Subagent (as a custom agent), Decision Journal, and adoption path form one coherent blocking handoff that meets every PRD acceptance signal.
